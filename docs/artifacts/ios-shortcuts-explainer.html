Amigo · iOS Shortcuts integration

You tap your card. The expense is already logged.

Nuno's integration lets your iPhone write to Amigo without you opening it. Here is every moving part, in the order a real payment travels through them — and the three places I changed how it behaves.

01

A token is how your phone proves it's you

Amigo's website knows you by a login cookie. Your iPhone's Shortcuts app has no cookie — it just fires off a bare web request. So Settings grows a card where you mint a personal access token: a long random string, shown to you exactly once.

What's stored in the database is only a one-way fingerprint of it, never the token itself. Same idea as your password. If someone stole the whole database, they still couldn't send a request as you.

The token is bound to whichever workspace was active when you created it. That's deliberate — an automation that silently changed which budget it wrote to, depending on what you'd last clicked, would be a nightmare.

What I changed

The token pointed straight at a workspace. It never re-checked that you were still a member of it. Kick someone out of a shared workspace and their phone keeps posting expenses into it forever. Now every request re-resolves through the membership record, exactly like the website does. No membership, no entry.

02

Two doors in

Apple Pay, hands-free

iOS has a Wallet trigger that fires on every card tap and hands you the merchant and the amount. The Shortcut forwards those two facts to Amigo. You don't touch your phone. You pay for coffee, the expense appears.

Wallet sends
{
  "merchant": "McDonald's",
  "amount":   "€ 12,40"
}

Siri, Back Tap, Action Button

Say or type it. The text runs through the same parser as the quick-add bar on the dashboard, so mcd 12 becomes McDonald's, €12.00, Lifestyle — with your keyword rules applied identically.

Siri sends
{
  "text": "mcd 12"
}
What I changed

That "€ 12,40" is messier than it looks. Currency symbols, comma decimals, dot thousands — and for a refund, some locales put the minus sign at the end: "12,34-". The old reader threw that minus away, so money coming back to you was recorded as money going out. It now reads the sign from either end, and refuses anything it can't parse cleanly rather than guessing.

03

What the server does with it

Every request runs the same gauntlet. The first three steps can throw it out; only the last one writes.

Gate Slow down Too many requests from one address, or one token, and it stops here.
Gate Who are you Fingerprint the token, find it, confirm you still belong to the workspace.
Read Make sense of it Parse the amount, clean the merchant, apply your keyword rules and category.
Gate Seen this already? Wallet sometimes fires twice for one payment. Catch the echo.
Write Log it Convert to EUR, save, reply with a line Siri can read back to you.

Worth knowing: this endpoint can only create expenses. It cannot read your data, cannot delete anything, cannot touch settings. A leaked token is an annoyance, not a breach.

04

The echo catcher, and why it was eating your coffee

Wallet occasionally sends the same payment twice. So the endpoint looks back in time: have I just seen this exact name and amount? If yes, it says "already logged" and writes nothing.

The problem was how far it looked. It scanned every expense in the whole workspace, from any source, over three minutes. That is indistinguishable from real life.

Situation Was Now
Wallet fires twice for one tap Caught Caught
You buy two coffees, tapping twice, 90s apart Second one vanished Both logged
You and Nuno buy the same lunch in a shared workspace His vanished Both logged
You type it in the web app, then Siri logs it too Siri's vanished Both logged
Two identical taps at the same shop within 60s Collapsed Still collapsed

Expenses now carry a stamp saying which token wrote them, so the echo check only ever compares a token against its own recent writes, inside a sixty-second window.

That last row is the honest cost. Two genuinely separate identical taps, less than a minute apart, at the same merchant, still merge into one. There is no way to tell that apart from a Wallet double-fire without asking you — and asking you defeats the point of it being silent. Sixty seconds is the trade.

05

If you'd rather look before it saves

There's a third mode that never posts anything. The Shortcut opens Amigo at /dashboard?add=mcd%2012, and the dashboard fills the quick-add bar with those words and focuses it — on mobile too, where that bar is normally hidden. Nothing is submitted. You read it, you press Add.

Good for the Action Button, when you want a beat of confirmation instead of blind trust.

06

Getting it live

The code adds a new table for tokens and a new column on expenses. Those don't exist in the live database yet, and deploy.sh does not create them.

Order matters

Deploy before pushing the schema and the app boots against a database missing both — every Shortcuts request returns a 500, and the Settings token card breaks. Schema first, always.

  1. Merge the follow-up PR so the fixes are on main alongside Nuno's work.
  2. Push the schema to the live database — creates the tokens table and the new column.
    $ ssh root@vibecode 'docker exec amigo npx prisma db push'
  3. Deploy with the sanctioned script, never docker compose directly.
    $ ssh root@vibecode 'bash /root/amigo/deploy.sh'
  4. Mint a token in Settings on your phone, and copy it — you only see it once.
  5. Build the Shortcut, following the guide that now sits in the Settings card.
07

What nobody has actually proven yet

The build is green and the amount reader is tested against seventeen awkward strings. But the tokens table doesn't exist in production until you run that schema push, so no part of this has ever run against a real token. Everything above is verified by reading the code and by the type checker — not by a phone.

Once it's deployed, check these four, in this order:

  • 1
    Mint a token, hit the connection test in the setup guide. It should greet you by workspace name.
  • 2
    Tap Apple Pay once. Exactly one expense, with the right merchant and amount.
  • 3
    Tap the same merchant twice, fast. Still exactly one — that's the echo catcher earning its keep.
  • 4
    Refund something, or fake one. It must land green, as a credit, not as another charge.
